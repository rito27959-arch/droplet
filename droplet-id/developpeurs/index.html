Une connexion qui ne demande rien à personne.

Ajoutez « Continuer avec Droplet ID » à votre site ou votre app. Vos utilisateurs approuvent sur leur téléphone ; vous recevez un identifiant stable, propre à votre service. Pas de numéro, pas d’e-mail, pas de nom, pas de mot de passe à protéger.

Continuer avec Droplet ID Continuer avec Droplet ID Continuer avec Droplet ID
  1. Votre site envoie la personne vers Droplet ID.
  2. Droplet ID affiche un code QR et un nombre à deux chiffres.
  3. Le téléphone scanne, la personne tape le nombre et approuve.
  4. Votre site reçoit un identifiant fait pour lui seul.

Démarrer en trois étapes

  1. Enregistrez votre site

    Écrivez à contact@dropletmesh.app avec le nom de votre service et vos adresses de retour exactes. Vous recevez un client_id. Pendant la phase de test, l’enregistrement est manuel.

  2. Ajoutez le kit de votre langage

    Un kit = une connexion vérifiée de bout en bout (PKCE, state, nonce, signature de l’ID token) et le bouton officiel.

  3. Gardez le sub

    C’est l’identifiant de la personne pour votre service. Stable d’une connexion à l’autre, différent sur chaque autre site. Ne redemandez pas de numéro ni d’e-mail pour vous connecter : c’est la promesse faite à vos utilisateurs.

Les kits

Kits vérifié : essayés de bout en bout contre le service, à chaque modification. Guides : la bibliothèque OpenID Connect habituelle du langage, avec la bonne configuration.

vérifié @droplet/id · navigateur · aucune dépendance · source

import { DropletId, boutonDropletId } from '@droplet/id';

const did = new DropletId({
  clientId: 'mon-site',
  redirectUri: location.origin + '/',
  portees: ['openid', 'profile'],   // 'profile' : le pseudo, si la personne accepte
});

if (did.estUnRetour()) {
  const { sub, pseudo } = await did.terminerConnexion();   // ID token vérifié
} else {
  document.body.append(boutonDropletId({ onClick: () => did.connecter() }));
}

guide Droplet ID suit OpenID Connect : la bibliothèque standard de votre langage suffit. Réglages communs : émetteur https://id.dropletmesh.app, flux authorization_code, PKCE S256, portées openid (+ profile), client public sans secret.

Java — Spring Security (application.yml)

spring.security.oauth2.client:
  registration.droplet:
    client-id: mon-site
    client-authentication-method: none
    authorization-grant-type: authorization_code
    redirect-uri: "{baseUrl}/login/oauth2/code/droplet"
    scope: openid
  provider.droplet:
    issuer-uri: https://id.dropletmesh.app

C# — ASP.NET Core

builder.Services.AddAuthentication(o => { o.DefaultScheme = "Cookies"; o.DefaultChallengeScheme = "droplet"; })
  .AddCookie("Cookies")
  .AddOpenIdConnect("droplet", o => {
      o.Authority = "https://id.dropletmesh.app";
      o.ClientId = "mon-site";
      o.ResponseType = "code";
      o.UsePkce = true;
      o.Scope.Clear(); o.Scope.Add("openid");
  });

Ruby — OmniAuth

use OmniAuth::Builder do
  provider :openid_connect,
    issuer: "https://id.dropletmesh.app", discovery: true,
    pkce: true, scope: [:openid], response_type: :code,
    client_options: { identifier: "mon-site", redirect_uri: "https://mon-site.cm/auth/openid_connect/callback" }
end

Swift — AppAuth-iOS

OIDAuthorizationService.discoverConfiguration(forIssuer: URL(string: "https://id.dropletmesh.app")!) { conf, _ in
  let req = OIDAuthorizationRequest(configuration: conf!, clientId: "mon-app", scopes: [OIDScopeOpenID],
                                    redirectURL: URL(string: "cm.monapp:/connexion")!, responseType: OIDResponseTypeCode,
                                    additionalParameters: nil)
  session = OIDAuthState.authState(byPresenting: req, presenting: self) { etat, _ in /* etat?.lastTokenResponse?.idToken */ }
}

Ces quatre guides utilisent les bibliothèques officielles de chaque langage ; ils n’ont pas encore d’essai automatique contre le service.

Référence

    

      
        
Émetteurhttps://id.dropletmesh.app · test : https://id-test.dropletmesh.app

        
Découverte/.well-known/openid-configuration

        
Fluxauthorization_code + PKCE S256 obligatoire · refresh_token à usage unique

        
Portéesopenid · profile (pseudo choisi par site) · offline_access. Il n’existe ni email ni phone.

        
Identifiantsub « pairwise » : un par site, stable

        
SignatureES256, clés sur /.well-known/jwks.json

        
DuréesID token 5 min · access token 10 min · refresh token 30 jours · code 60 s

        
Rester connectéSession Droplet ID : 14 jours dans le navigateur (cookie persistant). Session du site avec le kit JS : 30 jours (dureeSession), conservée après fermeture du navigateur.
